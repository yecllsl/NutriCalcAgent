# 饮食记录采集流程

## Overview

中文营养师的饮食记录采集助手，负责将食物照片/文本输入转化为结构化饮食记录并保存。核心流程：食物识别 → 营养分析 → 用户确认 → 保存记录。

## When to Use

- 用户说"记录一餐"、"录入饮食"、"拍照记录"、"我吃了..."
- 用户提供食物图片路径或直接输入食物名称
- 用户需要将进食记录保存到本地数据库

## Workflow

### 1. 获取输入
要求用户提供食物照片路径，或允许直接输入食物名称+份量。

### 2. 食物识别
调用 `recognize_food` Tool。
- 拍照模式：PaddleOCR 识别文字 + 返回视觉识别 prompt
- 文本模式：直接查本地食物库
- 失败时提示用户手动输入食物名称

### 3. 营养分析
调用 `analyze_nutrition` Tool，传入识别到的食物项（name + amount_g）。
- 本地库命中：按份量缩放营养素
- 未命中：返回估算 prompt，由 LLM 基于食材估算

### 4. 展示确认
将识别与分析结果以结构化格式展示给用户，请用户确认或修改：
- 菜名/食物名
- 份量（克）
- 烹饪法
- 餐次（早餐/午餐/晚餐/加餐）
- 进食时间

### 5. 保存记录
调用 `save_food_log`，自动生成 log_id（格式：fl_YYYYMMDD_NNN）。

## Quick Reference

| 步骤 | Tool | 降级方案 |
|------|------|----------|
| 食物识别 | `recognize_food` | 手动输入食物名称 |
| 营养分析 | `analyze_nutrition` | LLM 估算 prompt |
| 保存记录 | `save_food_log` | - |

## Common Mistakes

- **OCR失败直接报错**：应提示用户手动输入，而非终止流程
- **跳过用户确认**：识别和分析结果必须经用户确认后才保存
- **份量缺失**：必须确认食物份量（克数），否则营养分析无法计算
- **log_id格式错误**：必须使用 fl_YYYYMMDD_NNN 格式

## 约束规则

- 食物分类必须从标准列表选择
- 餐次限定4类：早餐/午餐/晚餐/加餐
- 记录必须包含 meal_time（进食时间）
